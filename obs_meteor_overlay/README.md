# OBSと旧UIの検出マスク同期

OBSの「直近の流星GIF」ブラウザソースで `dashboard.html` を読み込み、
ツール → スクリプトで `obs_meteor_overlay.lua` を登録します。
OBSを開いている間はプレビュー・配信の両方で更新し、終了すると更新処理を停止します。
従来の `index.html` を指定しても、新しい画面へ移動します。

## 配信画面の配置（1920×1080）

ライブ映像を左上、リプレイを右側、時計・1時間の検出数と推移・今夜の合計を下段に配置します。
OBSの「シーン」に次の変換を設定します。ブラウザソースの幅・高さは1920×1080、CSS欄は空です。
これらは配置の記録であり、Luaが利用者の配置を毎回上書きすることはありません。

| ソース | 位置（X, Y） | 拡大率 | 切り取り |
| --- | --- | --- | --- |
| メディア | 16, 16 | X・Yとも0.83 | 下72px、ほか0px（元の設定を維持） |
| 直近の流星GIF | 0, 0 | X・Yとも1.0 | なし |

双方とも左上基準、回転0、境界枠なしです。
ライブ映像は約1594×837pxで、右側のリプレイ領域（X1630〜1904、Y16〜853）と
下段（Y872〜1064）には重なりません。リプレイ枠は常に274×837pxで表示します。
新しいイベントを表示したときは、12秒間、外枠が金色になり「新しい検出」と表示します。
連続検出時は12秒を延長します。初回読み込みやマスク変更だけでは外枠の色を変えません。
GIFはイベント・マスク変更時だけ読み直し、
定期確認による再生の巻き戻りを避けます。

時計は日本時間で毎秒更新します。`hourly_stats.json` と今夜の合計は、旧UIの設定にある
`ml_training_data_root` の `reviewed/{meteor,not_meteor}/*/metadata.json` を優先して集計します。
`review_status=reviewed` の `reviewed_label` を正解ラベルとして使い、非流星への訂正は除外し、
非流星から流星への訂正は加算します。確認済み流星は元動画がアーカイブされても集計対象です。
未確認・スキップしたイベントは保存フォルダの自動判定を使います。確認済みだけの数ではありません。
サマリーと切り出し映像、データセット内の同じイベントは重複計上せず、フルサイズ映像は除外します。
流星・非流星の動画保存先と学習データの保存先は旧UIの保存設定に追従します。
訂正メタデータは5秒間隔で再確認し、変更されたファイルだけを読み直します。
現存するレビュー済みフォルダを読むため、レビューを取り消した場合も元の自動判定へ戻ります。
読み込み途中のJSONでは直前の正常な状態を保持し、データセットや元動画を書き換えません。
直近60分を10分ずつ6区間に分け、古い順に表示します。
窓は現在時刻に追従し、検出のない区間は0件です。
集計は更新処理の各巡回で出力し、GIF変換中は変換終了まで待ちます。
ブラウザは2.5秒ごとに集計を確認し、90秒以上更新されなければ「更新が遅れています」と表示します。
一時的な読み込み失敗では直前の表示を保ちます。

## 参照する旧UI設定

通常は `~/Library/Application Support/MeteorDetector/app_settings.json` を参照します。
このファイルがない開発環境では、プロジェクト直下の `app_settings.json` を参照します。
設定に `detection_mask_path` があればそのNPZを使い、なければ設定ファイルと同じ
フォルダの `app_masks.npz` を使います。相対パスは設定フォルダを基準にします。
SwiftUIへ移行・コピーされたマスクではなく、旧UIが使用する保存データを参照してください。

旧UIの検出マスクを確定すると、`apply_mask_var` の変更をきっかけに
`legacy_mask_sync.py` がマスクと適用状態を即時保存します。
「検出マスクを適用する」を解除した場合もOBSに反映します。
プレートソルブ用マスクは用途が異なるため、この同期の対象にはしません。
保存データの一時的な読み込み失敗時は直前の正常なマスクを維持し、ログに記録します。

## 映像への適用

カメラ映像には「旧UIの検出マスク（自動同期）」という画像フィルタを追加します。
Luaの設定でカメラ映像のソース名（初期値「メディア」）を指定できます。
旧UIと同じく0以下のマスク画素を黒にし、正の画素を表示します。
元の解像度でマスクを適用するため、OBSの位置・拡大率・切り取りにも追従します。
カメラの解像度とマスクが異なる場合はOBSフィルタ側で画像を伸縮します。
完全に同じ境界画素が必要な場合は、そのカメラ解像度で旧UIのマスクを作成してください。

右側の全体・拡大GIFは、保存されたイベント情報の元映像から生成します。
リプレイにも同じ訂正分類を使い、非流星に訂正された映像は表示対象から外します。
全体映像に水色の四隅マークを重ね、「水色の範囲を拡大 ↓」と拡大映像を同じ色で結びます。
`zoom_region` は拡大GIFと共通の切り取り計算から生成し、画像端の補正・全体GIFの余白も考慮します。
元映像の座標と拡大範囲が確定できない古い映像では、位置を推測せずマークを非表示にします。
元の動画やGIF画素に印を焼き込まず、ブラウザ上に重ねて表示します。
マスクは拡大部分の切り出し・縮小・GIF化より前に適用します。
マスクが変われば、イベントが同じでもGIFを作り直します。
元映像がなければ保存済みフルサイズ映像を使い、拡大部分もそこから切り出します。
その場合、保存時に既に黒くなっている領域を復元することはできません。
フルサイズ映像もないイベントは、誤った位置にマスクを適用する代わりに更新エラーを記録します。

設定・マスクは2秒間隔で確認し、カメラフィルタも2秒間隔で同期します。
GIFの更新には映像の変換時間が加わります。GIFと時刻は変換が成功した後に更新します。
保存画像・状態JSON・ログ・PIDは生成物としてGitから除外します。

## 手動起動

Python環境には `requirements.txt` のライブラリとffmpeg/ffprobeが必要です。
`launch_overlay.sh` はプロジェクトの `.venv-mac` とHomebrewのffmpegを優先します。

```bash
./obs_meteor_overlay/launch_overlay.sh --foreground
```

終了はControl+C。OBSのLuaスクリプトが登録済みの場合は自動起動を使ってください。
別の旧UI設定を参照する場合はPythonに `--legacy-settings /path/to/app_settings.json` を指定します。

旧UIを実行中にコードを更新した場合、即時保存を有効にするには旧UIの再起動が一度必要です。
OBS側はLuaスクリプトの再読み込みで反映できます。

## このカメラ専用の星座線

`build_sky_model.py` は録画の平均画像から中央の明るい恒星を照合し、
Tycho-2の全天星表から画面周辺まで対応を広げます。固定カメラのSTG投影と
5次の歪み補正を、実際に観測された恒星の位置へ直接フィットします。
汎用SIPの逆変換を画面の端まで外挿する方法には頼りません。
`refine_sky_model.py` は15分以上にわたる異なる時刻の3本以上の録画で、恒星時に従って移動する
対応だけを残し、ノイズや固定画素を除いて補正を再推定します。
確認した恒星の通過範囲から表示範囲を作り、その外側には線を出しません。

候補モデルは `calibration/camera_models/obs-camera-full-field/camera_model.json`、
配信で使う確認済みモデルは `calibration/approved/camera_model.json`、
目視確認用画像と数値は `validation/` に保存します。
旧UIの設定やプレートソルブ用キャッシュには登録しません。
以下は配信に表示されない候補作成・確認の例です。動画は同じカメラの完成済み録画を使います。

```bash
.venv-mac/bin/python obs_meteor_overlay/build_sky_model.py /path/to/rtsp/20261011/00/30.mp4
.venv-mac/bin/python obs_meteor_overlay/refine_sky_model.py \
  obs_meteor_overlay/calibration/camera_models/obs-camera-full-field/camera_model.json \
  /path/to/rtsp/20261011/00/00.mp4 /path/to/rtsp/20261011/00/30.mp4 /path/to/rtsp/20261011/00/45.mp4
.venv-mac/bin/python obs_meteor_overlay/verify_sky_model.py \
  obs_meteor_overlay/calibration/camera_models/obs-camera-full-field/camera_model.json \
  /path/to/rtsp/20261011/00/15.mp4 /path/to/rtsp/20261011/00/46.mp4
```

初回はAstrometry.net公式データ配布先 `https://data.astrometry.net/4100/` の
4100シリーズ15〜19（Tycho-2）をローカルへ保存します。映像の外部送信は行いません。
星座線の座標はプロジェクトの `assets/constellations.lines.json` を使います。
上記処理には既存の `.venv-mac` のastrometry・astropy・scipyも必要です。

適用前に、作成に使っていない録画の確認画像と、現在のカメラの確認画像で、
中央・周辺の星に線の端点が合っていることを目視で確認します。
目視確認後、候補モデルを `calibration/approved/camera_model.json` へコピーします。
これで次の候補作成が現在の配信モデルを上書きしません。
その後 `sky_config.json` に `enabled: true`、`model_path`、モデルファイルのSHA-256を
`approved_model_sha256`、目視確認日時を `visually_verified_at` として保存します。
`line_opacity` は不透明度0〜1で、現在は0.45（55％透過）の細い水色線です。
必要なら `video_delay_seconds` で配信映像の遅延秒数を指定します（初期値0）。
JSONは生成物でありGitには登録しません。モデルを書き換えるとハッシュが不一致になり、
再度確認するまで線を表示しません。`enabled: false` で星座線だけを停止できます。
カメラの向き・ズーム・解像度・OBSのライブ映像配置を変えたら、モデルと配置の再確認が必要です。

更新処理は別の低優先度プロセスで、時刻に合わせて5秒ごとに透過画像を作ります。
ブラウザは2.5秒ごとに読み込みます。表示範囲は旧UIの検出マスクにも追従します。
画像の更新が20秒以上止まった場合や確認済みモデルを読めない場合は、線を隠します。
ライブ映像や検出処理への新たなRTSP接続は作りません。
