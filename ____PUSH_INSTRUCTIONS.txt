Git push 手順と注意事項 (for `div` repository)

目的:
 - 誤ったディレクトリで git コマンドを実行して "fatal: not a git repository" が出る問題を防ぎ、将来の貢献者が安全に単一ファイルをコミット・プッシュできるようにする。

基本手順（単一ファイルを追加して push する最短手順）
1. リポジトリのルートがどこかを確認する
   - `git rev-parse --show-toplevel`
   - 実行ディレクトリが `div` リポジトリ内であることを必ず確認する。

2. 作業ツリーの状況確認
   - `git status --porcelain` で変更を一覧表示。
   - 変更ファイルが想定通りか確認する。

3. 単一ファイルをステージする
   - `git add path/to/file` 例: `git add lighten_blend_image.py`

4. コミットする（英語の短い説明を推奨）
   - `git commit -m "短く英語で変更点を書く"`
   - 例: `git commit -m "Improve lighten_blend_image: memory-limited compositing and mask handling"`

5. リモートとブランチを確認して push
   - `git remote -v` で `origin` が設定されているか確認
   - 現在のブランチ名を確認: `git branch --show-current`
   - push 実行: `git push origin HEAD` （現在のブランチを origin にプッシュ）

よくある失敗パターンと対処法
- エラー: "fatal: not a git repository"
  - 原因: コマンドを実行したカレントディレクトリに `.git` が無い。
  - 対処: `cd div` などで正しいリポジトリディレクトリに移動してから再実行する。上記の `git rev-parse --show-toplevel` が便利。

- エラー: push に拒否される (アップストリーム未設定等)
  - 対処: `git push --set-upstream origin <branch>` を一度だけ実行して upstream を設定する。

ベストプラクティス
- 事前に `git status` を見る習慣をつける。
- 1つの論理的変更は1コミットにする（コミットメッセージは英語で簡潔に）。
- 不安なときは `git add -p` を使いインタラクティブにステージする。

補助コマンド（トラブルシュート用）
- 現在のトップレベルを確認: `git rev-parse --show-toplevel`
- 現在のブランチ確認: `git branch --show-current`
- リモート確認: `git remote -v`
- コミットログ確認: `git log --oneline --decorate -n 5`

例: 作業の流れ（`div` ディレクトリにいる前提）
1) `git status --porcelain`
2) `git add lighten_blend_image.py`
3) `git commit -m "Improve lighten_blend_image: memory-limited compositing, mask handling"`
4) `git push origin HEAD`

このファイルを参照して、必ず `div` ディレクトリ内でコマンドを実行してください。
