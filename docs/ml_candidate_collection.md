# 学習候補の収集方針（旧UI）

通常の動画・画像はこれまでどおり流星判定に従って保存します。
「検出イベントを学習用フォルダへ追加する」がONのとき、主分類まで到達したイベントを以下の方針で未確認データとして収集します。前段の背景ゲートで除外されたイベントは対象外です。

| 候補 | 学習用の保存 |
|---|---|
| 流星判定：スコアがモデルの判定閾値以上 | 全件 |
| 境界付近：スコアが判定閾値の70%以上、判定閾値未満 | 全件 |
| それより低いスコア | 0.1%で抽出、一晩最大100件 |

旧UIの保存設定にある「判定閾値の直下を残す幅」は既定値0.30です。0.30は閾値直下30%を意味し、モデルを変更すると境界範囲も追従します。幅は0〜1で指定できます。0なら境界候補の全件保存を無効にします。旧設定の`ml_training_min_probability`は検出処理では使用しません。

例：v6の判定閾値0.0665705では、0.0665705以上を流星候補、約0.0465994〜0.0665705未満を境界候補として保存します。それより低い候補10,000件なら、抽出数の目安は約10件です。100件は上限であり、必ず100件収集する設定ではありません。

一晩はイベントの日時による正午〜翌日正午です。保存先ごとにカメラ・処理ワーカー・モデルの版をまたいで100件の枠を共有します。`collection_quota.sqlite3`に枠を記録するため、再起動やレビューによるファイル移動で上限がリセットされることはありません。別の保存先には別の枠が適用されます。

低スコア候補の抽出には入力元・イベント時刻・フレーム範囲・切り出し位置から作るハッシュを使います。同じ入力条件での再処理やモデル変更で抽出を引き直さず、同一の低スコアイベントは重複収集しません。ファイルを書き出す前に枠を確保し、通常の保存失敗時は枠を戻します。プロセスが強制終了した場合は、上限超過を避けるため確保済み枠を維持します。

イベントの`metadata.json`には以下を記録します。

- `collection.reason`：`predicted_meteor`、`decision_boundary`、`low_score_sample`
- 使用した判定閾値、境界幅、抽出率、上限、観測夜、イベント識別キー
- `model`：モデルのパス・重みのSHA-256・リリース識別子・前処理の版など

収集した候補はすべて`pending`です。学習には目視レビューで確定したラベルを使用します。既存データのラベルや確率は変更しません。
