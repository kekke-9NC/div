# 旧UIの配置・項目整理（2026-10-15）

既存の配色・フォント・機能を維持し、用途と作業順で配置を整理した。

| ページ | ページ内の分類 |
| --- | --- |
| 入力ソース | 動画・フォルダ / RTSPカメラ / 監視フォルダ / 実行の優先順位 |
| 出力・補正 | 保存先・保存物 / ノイズ低減 / カメラ校正 / 学習データ |
| 解析ツール | 解析・可視化 / 画像・動画作成 / 動画連結 |
| 詳細設定 | モデル・AI / 検出・処理 / クリップ |

- 保存先を保存物より先に表示。過去動画の自動処理は動画・フォルダへ、カメラ操作はRTSPへ、モデル作成は学習データへ移動した。
- 開始・停止・ライブ・進捗・残り時間は下部に固定。「次に開始する入力」は従来と同じ入力優先順位から計算する。
- 常設していた右ログペインは下部の開閉領域へ移動。ログを開いてもフォームの横幅を維持する。ログ内容は閉じても保持し、メニューや案内からのログ移動では自動的に開く。
- サイドバーの固定READY表示を、未確認データのレビューと流星保存先への入口に置き換えた。
- 案内・AIのリンクは入れ子のタブを開いて対象までスクロールする。案内中の「保存設定へ」は保存先・保存物を表示する。
- 説明ラベルは利用可能な幅で折り返す。ページとリストのスクロールを共通化し、他ページへの干渉・リストの二重スクロール・macOSの小さなホイール差分の切り捨てを防ぐ。

## 審査と確認

GPT-6 Lunaのサブエージェントに、全体構成、情報整理の差分、常設操作バー、ログ領域を段階的に審査依頼した。指摘されたリスト行の二重スクロール、モデル説明ラベルの順序、次回入力と実行中入力の混同を修正した。

実Tkで1480×900と1180×720の画面生成と主要導線を確認。1180×720では、全ページ内タブを走査し、ログを開閉した両状態で操作コントロールの横方向の欠けがないことを座標・要求サイズで確認した。設置後のv0.10.15.1を実際のappから起動し、タイトル、用途別タブ、保存設定の復元、常設操作バーをスクリーンショットでも確認した。

```sh
.venv-mac/bin/python -m pytest -q \
  tests/test_legacy_shell.py tests/test_legacy_layout.py \
  tests/test_gui_log_batch.py tests/test_gui_plate_solve_model_build.py \
  tests/test_legacy_shutdown.py tests/test_rtsp_fixed_pattern_modes.py
```

Tkのある環境で22件と6サブテストが成功。画面テストは検出処理やページ外部操作を起動しない。追加のアプリ全体スモークは、設定の読み書き・録画・起動時の再開処理を呼ばない検証用サブクラスで実施した。検出アルゴリズムや保存形式は今回の変更対象に含めていない。

## RTSP保存先を開く操作（v0.10.15.2）

GPT-6 LunaとRTSP画面内・保存先一覧・サイドバーメニューの案を検討し、さらに保存先の種類と表示の追従方法を議論した。録画を設定する文脈で見つけやすいよう、「入力ソース」→「RTSPカメラ」の録画スケジュール直前に「録画データ」を配置した。実装後もLunaによる配置・パス解決・エラー表示の審査を行った。

- 「録画保存先」と「自動生成物」のパスを表示し、各行の「開く」でFinderなどのファイル管理アプリへ移動する。時間帯指定がOFFでも利用可能。
- 録画は固定のRTSPルート、自動生成物は現在の出力先設定を開く。未設定時は`rtsp/schedule_products`、変更時は表示と操作先が即時追従する。過去の生成物は作成時の保存先に残る旨を表示した。
- 自動生成物の相対パスと`~`の扱いは生成処理と一致させた。日付別の子フォルダや内部キャッシュは操作先に含めない。未作成の保存先は案内を表示し、開く操作ではフォルダを作成しない。
- 流星・非流星の既存操作とフォルダを開く処理を共通化し、保存先がフォルダであることを確認する。ファイル管理アプリの起動エラーも画面に表示する。

関連する`test_legacy_shell.py`・`test_legacy_layout.py`・`test_gui_log_batch.py`・`test_legacy_shutdown.py`の15件が成功。全ページの実Tk生成を1180×720で確認し、ログ開閉の両状態でコントロールの横方向の欠けはなかった。保存先変更・未作成フォルダ・起動エラー・既存流星ショートカット・各OSの起動コマンドも確認した。

版表示はconfigの`0.10.15.2`、bootstrapの`2026.10.15.2`、Info.plistの短縮版`0.10.15.2`・build`20261015.2`へ更新。待機中の旧PID75060を正常終了し、同一ロックの排他取得中に変更4モジュールを実行先と同梱payloadの両方へ反映した。計8コピーのSHA-256一致、設定・マスクの更新前後の一致、実行先と同梱payloadの全トップレベルPythonファイルの一致を確認した。
