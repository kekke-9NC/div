# 旧UI：短い流星の検出改善（2026-10-11）

## 見落としの原因

対象は2026-10-11の02:18〜02:38ごろの元録画20本、計30,000フレーム。
目視確認済み29個のうち旧UIの保存済み実数は12個（保存13件中2件が同じ流星）。
旧UIと同じ曇天プリセット・マスク・分類モデルで段階別に再現した結果、
見落とし17個中9個は粗検出の候補なし、8個は移動点候補が得られたものの
詳細検出のHough線条件で不合格になっていた。

短い発光、縮小・平滑化による信号の減衰、短い軌跡への線長条件が影響する。
暗い候補を分類器へ渡す際は切り出し範囲にも注意が必要だった。
今回の原因を「分類モデルが17個を人工衛星と誤判定した」とする根拠はない。
分類器に届く前に落ちていた。

## 修正

- 元解像度で背景との差と位置移動を追跡する候補経路を追加。
- 1秒の処理窓を跨ぐ状態を保持し、2フレームだけの流星にも対応。
- 星の近くは背景に応じたしきい値を使う。固定星の明滅、まばらな光点の
  偶然の接続、遅い移動、長時間続く移動光点は運動の検証で除外する。
- 消光後の残像を発光時間に含めず、時間順に検証した候補を詳細検出へ渡す。
  その候補に再度長いHough線を要求しない。
- 暗い短い候補には周辺160px、通常は256px以上の領域を分類器へ渡す。
  全軌跡と周囲の空を確保し、機械学習向け保存でも同じ領域を使う。
- マスク、指定領域、画像端の除外を追加経路にも適用。
- 保存済み検出との重複判定に発光時刻を加え、同じ位置の後続流星を抑止しない。
  長い流星の隣接する切り出しは同一軌跡として統合。並列保存時も再確認する。

既存のHough・移動点候補経路は継続使用する。候補の運動だけで流星とは
確定せず、既存の分類器を通す。モデルの重みの再学習や判定しきい値の
引き下げはしていない。現在の分類器はmeteor_event_transformer_boost_v1、
判定しきい値は0.8822220810862557。

## 検証結果

|対象|結果|
|---|---|
|元の20分間全体を旧UIの実処理に通す|確認済み29個の29個を検出|
|前回の一覧外で追加発見した流星|27.mp4の326〜327フレーム、目視確認済み1個も検出|
|同じ流星の二重保存|25.mp4を修正版の並列処理で再検証し、1件に統合|
|最終的な20分間の出力|流星30件、非流星2件。流星30件は29個＋追加確認1個に対応|
|調整に使わない続く5分間（38〜42.mp4）、並列処理|保存済み流星1個を検出、新規2個も目視で流星と確認。非流星判定1件|
|単体・関連回帰テスト|17件成功|
|処理時間|録画1分あたり約22〜29秒（低優先度・CPU検証）|

全20分間は逐次経路を検証し、並列経路は続く5分間と二重保存のある25.mp4で検証した。
29個は調整に用いた回帰用データであり、未知の夜の精度100%を示す結果ではない。
続く5分間も検出した候補の目視確認と既知イベントの照合であり、
全流星の独立した正解個数を作成した評価ではない。
雲、非常に暗い単発の発光、虫・カメラ近傍の物体などを含む、より長い録画での
誤検出・見落としの評価は今後の課題になる。

## 再現

正解29個のフレーム位置は `tests/fixtures/short_flash_20261011.json`。
撮影時刻や特定の座標による例外は検出コードには含まない。
元録画・旧UIの設定・選択モデルが利用できる環境で実行する。

```sh
python tools/validate_short_flash_recall.py \
  --recording-root "/path/to/MeteorDetector/rtsp" \
  --settings "/path/to/MeteorDetector/app_settings.json" \
  --output "/tmp/short-flash-validation"
```

`--parallel` は並列詳細検出、`--baseline` は追加した短時間候補経路を無効にする。
検証はカメラに接続せず、配信の保存先・分類データ・設定を書き換えず、通知音も鳴らさない。

## インストールと適用

旧UIの実行先 `~/Library/Application Support/MeteorDetector` に、今回の変更を配置済み。
元ファイルは同ディレクトリの `backups/short-flash-20261011-*` に保存。
既存のインストール固有設定や別の作業の変更は保持している。

実行中の旧UIやOBSは再起動していない。旧UIの次回起動から有効になる。
配信を継続したい間はそのままにし、検出を止めてもよいタイミングで旧UIを再起動する。
