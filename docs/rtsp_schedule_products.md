# 旧UI: 録画スケジュール終了後の自動作成

「入力ソース」→ RTSP →「録画スケジュール」で時間帯指定をONにし、
「スケジュール終了後に自動作成」の必要な項目を選択します。
設定は既存のアプリ設定に保存されます。各項目は初期状態ではOFFです。

- タイムラプス: 初期設定15秒・60fps。RTSP検出マスクを適用し、録画スケジュール全体を均等に抽出します。天文薄明で時間範囲を絞りません。
- 比較明合成動画・画像: 流星と判定されたイベントのみを使用します。初期設定は座標による切り抜きです。`*_info.txt` の `Detected Line Start (px)`・`Detected Line End (px)` と同じ検出座標を起点に枠を作ります。短い検出線が軌跡の一部分だけを示している場合は、フレーム間の明るさの変化を使ってつながる軌跡の範囲を補完し、余白（初期値10px）を加えます。AIは使いません。256×256への拡大やリサイズは行わず、マイクロ流星も実際の軌跡に応じた小さい領域を元解像度のまま切り抜きます。枠が画面端を越える場合は画像範囲に収めます。通常の流星保存オプションがOFFでも素材を準備します。動画と画像は同じ保存済み切り抜きフレームを使用します。流星がない場合は合成をスキップしてログへ記録します。
- 等倍連結: 時系列で録画を連結します。互換性のある録画はFFmpegのstream copyを使います。スケジュール境界を越える場合やコーデック構成が変わった場合は、範囲をフレーム単位で整えて再エンコードします。FPS・解像度の変化はエラーとして元録画を保持します。

詳細設定では長さ、FPS、時間平均、時刻表示・位置・サイズ、線検出枠の余白、AI切り抜きのON/OFF、
出力先、配信の星座設定JSONを変更できます。星座はOBSの承認済みモデルと
同じ描画関数・不透明度を使用します。録画中の最初の描画時にモデルを固定し、
再起動後も同じモデルの内容を使います。設定JSONが空欄の場合は
アプリ横の `obs_meteor_overlay/sky_config.json` を読みます。
承認された星座モデルがない場合、星座ONのタイムラプスは失敗としてログへ記録し、
元録画を保持します。詳細設定で有効な配信設定を指定するか、星座をOFFにしてください。

録画中から別のワーカースレッドで抽出・星座描画・座標からの切り抜きを行います。
情報ファイルの書き込み前に同じ検出座標を受け取るため、情報ファイルを保存しない場合も
切り抜きを準備できます。内蔵AIは詳細設定で選択した場合だけ実行します。
AIの空応答・不正な枠・モデル起動失敗時は検出座標の枠を使います。
切り抜き済みPNGは比較明合成動画と画像で共有し、終了時に切り抜き直しません。
等倍連結も、確定した録画を最大10ファイルの区間に分けて先行作成します。
終了時は検証済みの区間キャッシュを使って連結し、足りない区間は元録画から補います。
スケジュール終了後、最後の録画区間のアーカイブ・解析・スプール整理が
完了してから生成します。解析が録画に追いついていない場合はその完了を待ちます。

出力は初期設定で `rtsp/schedule_products/<開始日時>_<終了日時>/` 内の
`timelapse.mp4`、`lighten.mp4`、`lighten.png`、`recording.mp4` です。
全ての選択した生成物が成功するまで元の録画を削除しません。
連結動画のフレーム数・FPS・解像度・先頭末尾のデコードを検証し、
生成物を公開して復旧情報を保存した後に元録画を削除します。
時間外の映像を含む境界ファイルは、時間外の映像を失わないよう保持します。
自動作成を一つも選んでいない通常のRTSP処理は、自動作成の長さ・FPSなどの
詳細設定に無効な値が保存されていても開始できます。

## キャッシュと復旧

`rtsp/.schedule_cache/` にPNGの一時素材・切り抜き済みフレーム・連結済みMP4を保存します。全スケジュール共通で
150,000,000,000 bytes（150GB）を上限とし、作成日時が古い素材から削除します。
「キャッシュ管理」から容量の確認・選択削除・全削除ができます。
キャッシュ操作は記録済みの元録画・完成した生成物を削除しません。
削除された素材は元録画から再取得します。連結中の入力キャッシュは処理が終わってから
削除します。作成中の連結キャッシュも容量を予約し、キャッシュ上限を共有します。

`rtsp/.schedule_jobs/` の復旧情報、イベントの時刻・検出枠、マスクはキャッシュから
分離して保存します。アプリ起動時に未完了スケジュールを自動で読み込み、
タイムラプス・切り抜き・連結キャッシュの欠落と破損を確認してバックグラウンドで補完します。
保存済みのAI判定・検出枠・マスク・星座モデルを再利用します。
以前の設定にAI切り抜きの指定がない未完了ジョブも、初期値の座標方式を使用します。
保存済みの検出枠を起点に元録画から軌跡の範囲を補完し、座標方式のキャッシュを作り直します。
以前のAI切り抜きと混同しません。元録画のアーカイブ待ちの場合は補完を待機します。
既存ジョブの余白は、そのジョブを開始した際の保存済み設定を引き継ぎます。
RTSPの開始操作を待たずに既存録画の準備を進めます。録画自体の再開は従来どおり開始操作が必要です。
RTSPを開始した場合は起動時のワーカーを共有し、二重生成を防ぎます。
終了前にUI設定を保存できなかった場合も、進行中スケジュールの保存済み生成設定を使って
再開後の流星素材を受け取ります。完了後の新しいスケジュールはUIの選択に従います。
RTSPの停止後も準備を続け、アプリを閉じると停止します。連結動画の公開後に中断された
元録画の削除も、生成物を再検証して続きから再開します。

流星素材は画像キャッシュより先に時刻・検出枠を登録します。キャッシュ保存や
マニフェストの更新に失敗すると復旧待ちにし、素材の再取得と登録が成功するまで
完了・元録画削除へ進みません。書き込み途中の中断は `capture.guard` でも検出します。
再起動後にイベントの登録情報自体が失われている場合は、流星なしとは扱わず、
元録画を保持してログへ記録します。その場合は検出情報の復旧が必要です。

内蔵AIを選択した場合はCUDAまたはApple SiliconのMPSを使用します。モデル未配置時は
既存のQwenモデルを取得するため初回は時間がかかります。AIが利用できない場合も
線検出の枠で合成できます。実際のカメラで一晩の処理時間は未計測です。
