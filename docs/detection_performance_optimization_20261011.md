## 変更内容

1. **動画フレームとマスクの再利用**：同じ詳細検出窓を何度も読み直す処理をまとめた。重なる窓は不足部分を読み込み、クリップも同じ画素から作る。主検出用の読み取り位置は独立している。不完全な読み取りでは従来の読み直し経路に戻る。
2. **必要な画素を先に選ぶ**：分類用の拡大画像と運動方向用の狭い範囲を取り出してからグレー変換する。変換とリサイズの順序を維持し、画素値が一致することを確認した。
3. **同じ計算を軽くする**：8ビット画素の中央値を小さい配列で計算する。中央値は整数または0.5単位であり、従来のfloat32と一致する。残差しきい値の比較も整数画素で同じ真偽になる形にした。
4. **追跡のまとめ処理**：近傍探索を同じ木・同じ距離計算でまとめて実行する。候補順位と同点時の順序を維持する。
5. **概要動画の並行保存**：検出と概要動画作成を重ねて進める。1動画あたり1保存ワーカー、未完了ジョブは最大2件。処理終了・キャンセル時には保存を完了してから戻る。保存結果の更新とUI通知は検出側のスレッドで行う。
6. **読み込みスレッドとコピーの整理**：概要動画にも2スレッドのデコーダーを使い、動画を送る際の不要な全画素コピーを減らした。比較明画像では、必要な最大値だけを計算する。

分類の重み・しきい値、提案候補の条件、解像度、フレームレート、クリップの時間範囲、動画のコーデックと画質設定を維持している。
